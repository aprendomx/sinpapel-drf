# sinpapel-drf v0.2.0 — Diseño de endpoints para features v0.4.0 del padre

**Fecha:** 2026-05-15
**Estado:** Aprobado por usuario, pendiente plan de implementación
**Versión sinpapel-drf:** 0.1.1 → 0.2.0
**Versión sinpapel (padre):** v0.1.1 → v0.4.0

## Contexto

`sinpapel-drf` es la capa HTTP DRF para la librería `sinpapel`. El paquete padre
saltó de v0.1.1 a v0.4.0 con 5 features mayores:

1. **Predicados de transición** (`CondicionTransicion` + `PredicateEngine`)
2. **Captura de metadatos estructurados** (`MetadatosCapturables` + `MetadatosProxy`)
3. **Form/Serializer Factory** (`MetaFormFactory.build_serializer`)
4. **Timers / SLAs** (`SLAConfiguracion` + `SLAEngine` + management command)
5. **Preview de transición** (`WorkflowEngine.preview_transition` con impact report)

Ninguna está expuesta por HTTP. Este spec define los endpoints, serializers,
contratos y plan de pruebas para cerrar el gap.

## Decisiones clave del usuario

- Alcance: **full** — las 5 features.
- CRUD predicados/SLAs: **ModelViewSets independientes**.
- Metadatos: **PATCH parcial + schema embebido en GET**.
- SLA: incluye **POST /slas/verificar/** + **GET sla-status** por instancia.

## Endpoints

### A. Preview Transition (per-resource, dinámico via SinpapelRouter)

`POST /<slug>/<pk>/preview-transition/`

**Request:**
```json
{ "target_state": "Aprobado" }
```

**Response 200:** reporte de `WorkflowEngine.preview_transition()`:
```json
{
  "permitido": true,
  "razones_bloqueo": [],
  "documentos_faltantes": [],
  "predicados_fallidos": [],
  "aprobadores_requeridos": [],
  "side_effects": [],
  "historial_reciente": [
    {"fecha": "...", "transicion": "Borrador → Revisión", "usuario": "alice", "comentarios": "..."}
  ]
}
```

**Permission:** `IsAuthenticated`. NO requiere ser admin: cualquier usuario
autenticado puede simular para descubrir bloqueos UI-side. La simulación NO
muta nada, NO ejecuta side-effects.

**Errores:** 400 si `target_state` falta o no es string. El engine NO levanta
excepciones desde preview — todo bloqueo viene reflejado en `permitido=false`.

### B. Metadatos (per-resource, dinámico)

`GET /<slug>/<pk>/metadatos/`

**Response 200:**
```json
{
  "schema": [
    {"nombre": "rfc", "tipo": "str", "requerido": true, "default": null,
     "choices": null, "etiqueta": "RFC", "ayuda": "..."}
  ],
  "values": { "rfc": "ABCD010101ABC" }
}
```

`PATCH /<slug>/<pk>/metadatos/`

**Request:** subset de campos del schema (partial).
**Response 200:** `instance.meta.to_dict()` actualizado.

**Permission:** `IsAuthenticated`. Política de quién puede mutar metadatos
queda fuera de scope del paquete; el consumer puede sobreescribir.

**Errores:**
- 400 si tipo incorrecto, choice inválido, validación de `clean()` falla.
- 400 si key fuera del schema (`AttributeError` del proxy mapeado).

### C. Condiciones de Transición (top-level ModelViewSet)

`GET /condiciones/` — list con filtros `?transicion=<id>&activo=<bool>`
`POST /condiciones/` — create
`GET /condiciones/<pk>/`
`PATCH /condiciones/<pk>/` / `PUT /condiciones/<pk>/`
`DELETE /condiciones/<pk>/`

**Serializer:** `ModelSerializer` sobre `CondicionTransicion` con `fields="__all__"`.
**Permission:** `IsAdminUser` — los predicados son configuración de negocio crítica.
**Filtros:** simple `django-filter` o filtro manual en `get_queryset()`.

### D. SLAs (top-level ModelViewSet + acciones)

`GET /slas/` — list con filtros `?estado=<id>&activo=<bool>`
`POST /slas/`, `GET/PATCH/PUT/DELETE /slas/<pk>/`

`POST /slas/verificar/` — dispara `SLAEngine.verificar_todos()`. Returns `{"ejecutadas": {"notificar": 3, "escalar": 1, ...}}`.

`POST /<slug>/<pk>/sla-status/` — evalúa SLA per-instance vía
`SLAEngine.evaluar_instancia(instance)`. Retorna lista de acciones ejecutadas
si SLA vencida (puede mutar la instancia: `_accion_alertar` setea campos), o
`[]`. Se usa POST porque `evaluar_instancia` tiene side-effects (ADR REST:
GET nunca debe disparar mutaciones).

**Permission:** `IsAdminUser` para CRUD y verificar. `IsAdminUser` también para
sla-status (mismas razones que verificar — dispara acciones).

**Errores:** 400 si `unique_together (estado, accion_vencimiento)` se viola.

## Serializer Factory — integración

`MetaFormFactory.build_serializer(schema)` ya existe en `sinpapel.forms`. La
integración consiste en construir y cachear la subclase Serializer por modelo:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def get_meta_serializer_class(model_cls):
    return MetaFormFactory.build_serializer(model_cls.SCHEMA_METADATOS)
```

El cache es seguro porque `SCHEMA_METADATOS` es `ClassVar` inmutable (frozen
dataclass items). El `MetadatosView.patch()` usa este cache con `partial=True`.

`_campo_to_dict` (helper) mapea `CampoMetadato` a JSON serializable. Tipo
serializado como string (`"str"`, `"int"`, `"bool"`, `"Decimal"`, `"date"`).

## Error mapping (extiende S13.5 D3)

| Excepción interna | HTTP | Notes |
|---|---|---|
| `ValueError` (engine, schema, factory) | 400 `ValidationError` | reuso existente |
| `PermissionError` (engine) | 403 `PermissionDenied` | reuso existente |
| `django.core.exceptions.ValidationError` (mixin clean) | 400 `ValidationError` | NEW — mapea `.message_dict` a DRF |
| `SignatureValidationError` / `SignatureBackendNotConfiguredError` | 400 | reuso |
| `TypeError` (proxy.__setattr__ tipo incorrecto) | 400 `ValidationError` | NEW |
| `AttributeError` (proxy key fuera de schema) | 400 `ValidationError` | NEW |
| `DoesNotExist` (condicion/sla pk) | 404 | DRF default |
| `IntegrityError` (unique_together SLA) | 400 | mapea en serializer validate |

## Serializers nuevos

```python
# serializers.py adiciones

class PreviewTransitionRequestSerializer(serializers.Serializer):
    target_state = serializers.CharField(required=True, allow_blank=False)

class PreviewTransitionResponseSerializer(serializers.Serializer):
    permitido = serializers.BooleanField()
    razones_bloqueo = serializers.ListField(child=serializers.DictField())
    documentos_faltantes = serializers.ListField(child=serializers.DictField())
    predicados_fallidos = serializers.ListField(child=serializers.DictField())
    aprobadores_requeridos = serializers.ListField(child=serializers.DictField())
    side_effects = serializers.ListField(child=serializers.CharField())
    historial_reciente = serializers.ListField(child=serializers.DictField())

class CampoMetadatoSerializer(serializers.Serializer):
    """Readonly — para GET /metadatos/ schema."""
    nombre = serializers.CharField()
    tipo = serializers.CharField()  # "str" | "int" | "bool" | "Decimal" | "date"
    requerido = serializers.BooleanField()
    default = serializers.JSONField(allow_null=True)
    choices = serializers.ListField(child=serializers.CharField(), allow_null=True)
    etiqueta = serializers.CharField(allow_blank=True)
    ayuda = serializers.CharField(allow_blank=True)

class CondicionTransicionSerializer(serializers.ModelSerializer):
    class Meta:
        model = CondicionTransicion
        fields = "__all__"

class SLAConfiguracionSerializer(serializers.ModelSerializer):
    class Meta:
        model = SLAConfiguracion
        fields = "__all__"
```

## URL routing final

```python
# urls.py
from rest_framework.routers import DefaultRouter

router = SinpapelRouter()  # dinámico per-resource
admin_router = DefaultRouter()
admin_router.register("condiciones", CondicionTransicionViewSet,
                      basename="condicion")
admin_router.register("slas", SLAConfiguracionViewSet, basename="sla")

urlpatterns = router.urls + admin_router.urls + [
    path("flujos/<int:pk>/export/", FlujoExportView.as_view(), name="flujo-export"),
    path("flujos/import/", FlujoImportView.as_view(), name="flujo-import"),
]
```

`WorkflowViewSet` gana 3 `@action` nuevos: `preview_transition`, `metadatos`
(con `methods=["get", "patch"]`), `sla_status`. Estos se exponen
automáticamente por instancias dinámicas de `build_viewset_for(config)`.

`metadata_views.py` exporta helpers (`get_meta_serializer_class` con `lru_cache`,
`campo_to_dict`) que el WorkflowViewSet importa. Las 3 acciones (preview, metadatos,
sla-status) viven como `@action` del WorkflowViewSet — así `SinpapelRouter`
las publica automáticamente para cada modelo workflow-enabled sin URL extra.

## Plan de pruebas

Cubrir cada endpoint nuevo con `pytest-django` + `APIClient` + `factory_boy`:

### Preview transition (~5 tests)
- happy path: `permitido=true`
- bloqueado por permiso (grupo no autorizado)
- bloqueado por predicado fallido
- bloqueado por documento faltante
- estado destino inexistente → `permitido=false` con razón

### Metadatos (~7 tests)
- GET retorna schema con todos los campos
- GET retorna `values` correctos
- PATCH partial: solo actualiza key provista
- PATCH required field con null → 400
- PATCH choice inválido → 400
- PATCH tipo incorrecto → 400
- Isolation entre instancias (PATCH a A no afecta B)

### Condiciones CRUD (~7 tests)
- list con `?transicion=` filtra
- list con `?activo=false`
- create con configuracion json_logic válida
- update toggling `activo`
- delete
- non-admin → 403
- configuracion JSON inválida → 400 (vía PredicateEngine validation si aplica)

### SLAs CRUD + ejecución (~9 tests)
- list con `?estado=` filtra
- create con accion_vencimiento=notificar
- update `dias_maximos`
- delete
- non-admin → 403
- `unique_together (estado, accion_vencimiento)` violada → 400
- `POST /slas/verificar/` retorna conteo
- `POST sla-status` con SLA vencida ejecuta acción
- `POST sla-status` sin vencer retorna `[]`
- `POST sla-status` con non-admin → 403

**Total nuevo:** ~28 tests. Target: suite existente (1006 tests) sigue verde.
